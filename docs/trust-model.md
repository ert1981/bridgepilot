# مدل اعتماد: BridgePilot یک بریج «مبتنی بر اعتماد به امضاکنندگان» است

> این سند صریح است تا هیچ‌کس آن را «بدون نیاز به اعتماد» یا «کاملاً امن» تلقی نکند.

## ۱. چه چیزی را قرارداد اثبات می‌کند و چه چیزی را نه

| قرارداد اثبات **می‌کند** | قرارداد اثبات **نمی‌کند** |
|---|---|
| دست‌کم `threshold` امضاکننده فعلی (اکثریت مطلق) این پیام دقیق را امضا کرده‌اند | که تراکنش مبدأ واقعاً روی زنجیره مبدأ رخ داده و نهایی شده است |
| پیام برای همین شبکه، همین قرارداد و همین نوع (lock / burn / refund) است | که امضاکنندگان مستقل و صادق‌اند |
| پیام قبلاً اجرا یا لغو نشده است | |
| آزادسازی از پشتوانه همان شبکه بیشتر نیست؛ بازپرداخت فقط برای پیامی که واقعاً همین‌جا آغاز شده | |

قرارداد **light client یا اثبات رمزنگاری‌شده وضعیت مبدأ ندارد** (هنوز). معماری برای حذف تدریجی این اعتماد طراحی شده است: قراردادهای بریج از طریق `VerifierRouter` تأیید می‌کنند و هر مسیر می‌تواند فقط **یک‌طرفه** (بدون کاهش سطح، با تأخیر ≥ ۷ روز، وتوی guardian و تاریخچه روی زنجیره) به verifier رمزنگاری‌شده ارتقا یابد — جزئیات در [`verifier-upgrade.md`](verifier-upgrade.md). تا وقتی چنین verifierی برای یک مسیر فعال و مستقلاً ممیزی نشده، آن مسیر trust-based است. صحت رویداد مبدأ را امضاکنندگان (off-chain) بررسی می‌کنند. اگر هدف نهایی تأیید بدون اعتماد به امضاکنندگان است، این معماری هنوز به آن نرسیده و مسیر آن (light client / ZK برای هر خانواده شبکه) پروژه جداگانه‌ای است.

## ۲. اگر `threshold` امضاکننده تبانی کنند یا کلیدشان دزدیده شود

می‌توانند پیام جعلی بسازند. حداکثر خسارت **به‌ازای هر توکن و هر شبکه** محدود است:

| مسیر حمله | سقف خسارت |
|---|---|
| ضرب جعلی روی شبکه راه دور | `supplyCap[token]` آن شبکه، و سرعت آن ≤ `buckets` (rate limit) |
| آزادسازی جعلی روی شبکه خانه | `lockedFor[token][آن شبکه]` ≤ `chainCap`؛ سرعت ≤ rate limit |
| بازپرداخت جعلی (برای پیامی که اجرا شده) | فقط پیام‌هایی که واقعاً آغاز شده‌اند (`initiated`)، هرکدام یک‌بار؛ سرعت ≤ `refundBuckets` |

خسارت تا زمان کشف ≈ `min(cap, ظرفیت + ظرفیت × زمان‌واکنش / پنجره)`. **سقف قابل قبول (`maxChainCap`) و زمان واکنش (`reactionTimeSec`) تصمیم کسب‌وکار است؛ اما gate آمادگی آن‌ها را اجباری می‌کند** و استقرار را تا وقتی سقف‌ها و همه سطل‌های rate limit درون این بودجه نباشند «آماده» اعلام نمی‌کند.

## ۳. شرط‌های لازم برای اینکه «۲ از ۳» واقعاً ۲ از ۳ باشد
- **attesterهای در حال اجرا = signer set قرارداد:** gate آدرس attesterهای در حال اجرا و اعلام‌شده را دقیقاً با `signers()` هر شبکه مقایسه می‌کند (نه فقط تعداد).

`protocol/verify-deployment.ts` این‌ها را از پیکربندی `attesters` بررسی می‌کند و در صورت نقض، استقرار را «آماده» اعلام نمی‌کند:
- **اپراتورهای مستقل:** تعداد اپراتورهای متمایز ≥ `threshold` (هیچ نهادی به‌تنهایی به آستانه نرسد).
- **نگهداری کلید:** HSM یا KMS؛ کلید در فایل = خطا.
- **RPC مستقل:** هر attester برای هر شبکه دست‌کم ۲ **اپراتور** RPC مستقل اعلام‌شده در ثبت‌نامه `rpcProviders` (نه دو دامنه؛ اپراتورهای با IP مشترک یکی حساب می‌شوند)، و `quorum` در `ChainView` تا یک RPC دروغگو یا عقب‌مانده نتواند باعث امضا شود. ارائه‌دهنده مشترک میان ≥ `threshold` attester هشدار می‌گیرد.
- **finality:** `probeFinalityRpc` بررسی می‌کند endpoint تگ `finalized` را درست گزارش کند (موجود، ≤ latest، بدون عقب‌ماندگی غیرعادی). درستی تگ `finalized` در خود نود همچنان یک فرض است؛ با quorum چند ارائه‌دهنده کاهش می‌یابد، حذف نمی‌شود.

## ۴. اختیارات مدیریتی
- مدیریت = `TimelockController` خودگردان (هیچ admin بیرونی)، با تأخیر ≥ ۲ روز (کف پروژه در کد، `POLICY.minTimelockDelaySec`؛ پیکربندی فقط می‌تواند سخت‌گیرانه‌ترش کند)؛ همه دارندگان نقش‌ها از تاریخچه رویدادها بازسازی و دقیقاً با سیاست مقایسه می‌شوند؛ multisig باید یک Safe پذیرفته‌شده با مالکان و آستانه اعلام‌شده و بدون module باشد؛ فقط multisig پیشنهاد، اجرا و لغو می‌کند؛ اجرای باز برای همه ممنوع.
- pauser جدا: فقط توقف. راه‌اندازی دوباره فقط از timelock.
- مدیریت **نمی‌تواند** وجوه قفل‌شده را جابه‌جا کند، اما می‌تواند (با تأخیر) peer، توکن، سقف و مجموعه امضاکنندگان را عوض کند. تأخیر timelock زمان واکنش کاربران و پایش است.

## ۵. تصمیم پیش از هر شبکه اصلی
پیش از mainnet، این موارد باید **بررسی مستقل** شوند: مدل تهدید، استقلال واقعی اپراتورها، فرایند مدیریت کلید، سقف خسارت هر شبکه، زمان واکنش پایش و توقف اضطراری، و ممیزی قراردادها. تا آن زمان قراردادها فقط روی شبکه‌های آزمایشی allowlist‌شده مستقر می‌شوند.
